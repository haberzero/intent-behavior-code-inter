# 宏观健康诊断（Code Health Diagnosis）

## 做什么

对代码子系统做系统性体检，覆盖死代码到架构耦合的全谱系问题，产出**分类证据 + 推荐动作**。只诊断不改码——修复走 `code-workflow`，实施后核验回 `code-review`。

## 何时使用

- 检查某模块健康度 / 清洁度，或怀疑"还有历史痕迹 / 残留"
- 大批量重构 / 子系统重写之后，验证旧模式是否清零（实施后核验）
- 改动一个子系统前摸清其真实状态；交付前对久未触碰的代码做体检

## 诊断十查

1. **死代码与残留**：未用导入 / 属性 / 参数 / 返回值；零消费者方法；死分支与恒真恒假 guard；注释掉的代码块；copy-paste 重复实现；**两套机制做同一件事**（同一概念两种实现必漂移，合并或删一套）
2. **损坏空壳**：引用未初始化 / 已删除字段的方法；声明即坏的用户面 API（vtable / 协议）；stub 占位"先这样"；静默回退（`except: pass`、`return None` 掩盖路径）
3. **字面量散落**：魔法字符串 / 数字 / 哨兵重复；同义字面量跨层镜像（靠注释"保持同步"）；硬编码路径 / URL / 超时；应提炼单点常量
4. **半接通特性**：协议 / 框架已落地但零消费者，或消费者从不触发（恒参、恒 false、从不传非默认值）；声明未实现；实现未接线
5. **架构与耦合卫生**：层穿透（低层 import 高层）；循环依赖；上帝对象 / 超长模块；职责错位；**协议与实际签名漂移**（用 `hasattr` 探测能力而非协议声明，即穿透封装）
6. **状态与并发卫生**：只写不读的状态；可变共享状态未隔离；全局单例可变槽；线程安全边界不清；无失效机制的无界缓存
7. **错误处理卫生**：裸 `except` / `except: pass` 吞异常；宽捕获后泛化抛出丢上下文；静默 fallback 违 fail-fast（应 raise）；异常路径无测试
8. **命名与风格卫生**：命名与行为不符；内建名遮蔽；无意义 / 不一致命名；`hasattr` / `setattr` 穿透私有属性；同一概念多处不同叫法
9. **测试与覆盖卫生**：公开 API 零覆盖；测试断言与行为不符；测试间共享可变状态（隔离破坏）；测试名与所做之事不符；测试依赖"凑巧相等"
10. **文档漂移**：示例 / 说明与真实返回类型或行为不符；注释与代码矛盾；过时 docstring；单点真理被重复定义（概念两处描述必漂移）

## 证据优先工作流

1. **全仓取证**：grep 消费者、字面量、已删符号残留；读实现、测试、协议、文档；用 `git log -S <symbol>` 查历史意图（区分死代码与废弃接口）
2. **每条发现**给 `file:line` + 行为证据 + 分类，禁止无证据断言；矛盾以源代码 > 测试 > 设计文档裁决
3. **分类先行**（见速查表）；合并讨论仅当【问题本质 + 修复方案 + 架构层级】三者全一致
4. **产出报告**：分类清单 + 每类推荐动作（删除 / 激活 / 修复 / 文档化 / 一致性测试）；区分"我引入的"与"预存的"，前者直接修，后者待决策
5. **修复由用户决策**；实施后残留扫描须覆盖修复范围之外（含同类其它模块），零残留才提交

## 分类速查

| 现象 | 分类 | 默认动作 |
|---|---|---|
| 零消费者 + 无设计意图 | 死代码 | 删除 |
| 零消费者 + 有设计意图 + 契约完好 | 预留未激活 | 激活或文档化 |
| 有调用点但逻辑为空 / 损坏 | 功能空壳 | 删除（违架构）或实现（有需求） |
| 恒参 / 恒 false / 从不触发 | 死分支 | 删分支；协议签名向后兼容则保留 |
| 层约束导致的镜像常量 | 设计限制 | 一致性测试取代人工同步 |
| 文档与代码不符 | 文档漂移 | 以代码为准修文档 |
| 注释含代号 / 历史 | 卫生违规 | 改写注释 |
| 两套机制同一概念 | 架构漂移 | 合并为一套，删另一套 |

## 自查 grep 速查

- 未用导入：`grep -rn "import X"` 后对照全仓引用数（仅定义处命中 = 死导入）
- 吞异常：`grep -rn "except:"`、`grep -rn "except Exception: *pass"`
- 零消费者：`grep -rn "symbol" --include="*.py" | wc -l` == 1
- 镜像常量：跨文件 grep 同名 / 同义常量；大写字面量比对
- 层穿透：低层包路径下 grep `import <高层包>`
- 未用配置：grep 配置键，核对读 / 写两侧命中数

## 与其他 skill 的关系

- **code-review**：对已报告缺陷独立验证、批量变更后核验完整性、规则永久化
- **code-workflow**：诊断确认方向后的实现（修复 / 删除 / 重构）
- **doc-governance**：涉及 `docs/` 技术文档修改时的书写纪律

本 skill 产出诊断报告；修复进入 `code-workflow`，实施后核验回到 `code-review`。
