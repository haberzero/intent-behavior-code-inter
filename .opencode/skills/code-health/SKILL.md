# 宏观健康诊断（Code Health Diagnosis）

## 做什么

对代码子系统做系统性体检，找出历史残留、死代码、质量缺陷与文档漂移，产出**分类证据 + 推荐动作**的诊断报告。本 skill 只诊断不改码——修复走 `code-workflow`，实施后核验回 `code-review`。

## 何时使用

- 用户要求检查某模块的健康状况 / 清洁度，或怀疑"还有历史痕迹 / 残留"
- 大批量重构、迁移、子系统重写之后，验证是否遗留旧模式（实施后核验）
- 交付前对长期未触碰的代码做体检，或在改动一个子系统前摸清其真实状态

## 诊断六查

1. **死代码与残留**：未使用导入 / 属性 / 参数、零消费者方法、死分支、恒真 guard、只写不读的配置项
2. **损坏空壳**：引用未初始化或已删除字段的方法、声明即坏的用户面 API（vtable / 协议层）
3. **字面量散落**：魔法字符串 / 哨兵重复出现、同义字面量跨层镜像、重复的判定 tuple
4. **半接通特性**：协议 / 框架已落地但无消费者，或消费者从不触发（恒参、恒 false 分支、从不传非默认值的参数）
5. **文档漂移**：文档示例 / 说明与真实返回类型、真实行为不符（以代码为准修文档）
6. **卫生违规**：注释含 ADR / PT / 任务代号编号、历史叙述、单点真理被重复定义

## 证据优先工作流

1. **全仓取证**：grep 消费者、字面量、已删除符号的残留引用；读实现、测试、协议声明、文档
2. **每条发现**给 `file:line` + 行为证据 + 分类，禁止无证据断言；矛盾以源代码 > 测试 > 文档裁决
3. **分类先行**（见速查表）；合并讨论仅当【问题本质 + 修复方案 + 架构层级】三者全一致
4. **产出分类报告**：真死代码 / 空壳 / 半接通 / 预留 / 设计限制 / 文档不符 + 每类推荐动作（删除 / 激活 / 修复 / 文档化）
5. **修复范围由用户决策**；执行后做残留扫描，覆盖范围须超出修复分配的范围（含同类其它模块）

## 分类速查

| 现象 | 分类 | 默认动作 |
|---|---|---|
| 零消费者 + 无设计意图 | 死代码 | 删除 |
| 零消费者 + 有设计意图 + 契约完好 | 预留未激活 | 激活或文档化 |
| 有调用点但逻辑为空 / 损坏 | 功能空壳 | 删除（违架构）或实现（有需求） |
| 恒参 / 恒 false / 从不触发的分支 | 死分支 | 删分支；协议签名若向后兼容则保留 |
| 层约束导致的镜像常量 | 设计限制 | 一致性测试取代人工"保持同步"注释 |
| 文档与代码不符 | 文档漂移 | 以代码为准修文档 |
| 注释含代号 / 历史 | 卫生违规 | 改写注释 |

## 与其他 skill 的关系

- **code-review**：对已报告缺陷独立验证、批量变更后核验完整性、规则永久化
- **code-workflow**：诊断确认方向后的实现（修复 / 删除 / 重构）
- **doc-governance**：涉及 `docs/` 技术文档修改时的书写纪律

本 skill 产出诊断报告；修复进入 `code-workflow`，实施后核验回到 `code-review`。
