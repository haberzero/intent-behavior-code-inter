## 三、通信机制设计空间（前期分析）

通信模型全景（不同问题域，非同一事物的别名）：

| 模型 | 本质 | 解决"什么" |
|------|------|-----------|
| 管道 Pipe | 连续字节/消息流 | 流式传输（有序、连续） |
| 槽 Slot | 具名位置存/取值 | 共享状态（读写、单值） |
| 信箱 Mailbox | 向接收者发消息队列 | 点对点消息（离散、排队） |
| 订阅 Pub/Sub | 订阅者接收事件 | 多点广播（扇出、异步） |
| 消息 Message | 离散消息 | 请求/响应/通知 |
| 中断 Interrupt | 异步抢占式信号 | 控制/打断（一次性、抢占） |
| 全局单例 | 共享全局状态 | 跨点共享 |

**三个正交的通信域**（不能用一个"超抽象"覆盖，需三协调抽象）：

1. **数据流域**：Channel（带 `mode` 参数统一 stream/message/pubsub）
2. **控制流域**：Signal（中断/取消/暂停，非数据，抢占式）
3. **共享状态域**：Slot（具名可反复读写，原子）

**结论**：单个"Channel"不够；需 Channel + Signal + Slot 三抽象，共享统一内核。

## 四、核心机制设计

### 4.1 Channel（数据流地基）

```
Channel<类型 T>:
  - buffer: 有界缓冲（大小可配）
  - source: 生产者（可多个）
  - sink: 消费者（可多个）
  - mode: stream（有序流FIFO）/ message（离散排队）/ pubsub（扇出）
  - ops: send / recv / send_blocking / recv_nonblocking / close
  - 线程安全：读写在多线程间安全
```

### 4.2 Signal（控制流，独立于数据流）

```
Signal(type: SignalType, target: Optional[Handle] = None)
  - target=None → 广播（全局）
  - target=H   → 定向（单目标）
  - 类型：cancel / pause / resume / config_change
  - 语义：一次性、抢占式、可绑定到目标
```

### 4.3 Slot（共享状态域）

```
Slot<类型 T>:
  - 具名：name
  - 语义：可反复读写，原子更新（读改写）
  - 关系：Channel 的"最后值"即 Slot 视图（可互相转换）
```

### 4.4 统一通信内核

- 三抽象共享：线程安全 bounded buffer、可寻址注册表（供广播枚举 + 定向查找）、可内省、可控制。
- 语言层全部暴露为一等公民（有类型，接受破坏性改造）。

## 五、内省层（快照 + 事件流）

- **快照式**：`runtime.snapshot()` 查询当前所有在途任务/Channel/Slot 状态。
- **事件流**：`runtime.subscribe()` 订阅状态变更 + 流式数据。
- 内省是**通用、可复用、不过时**的机制（对标 Python `sys.settrace`/`inspect`、`asyncio.all_tasks()`、OpenTelemetry spans），不是 LLM 专有伪设计。

---

## 六、控制层（统一启停，非"关闭接口"）

- 每个可控制能力有"开启/关闭"两侧，默认值不同。
- `runtime.configure(parallel=, stream=, observability=, debug=)`。
- 粒度：全局 → 单调用 → 单实例（链式覆盖）。
- 默认值：并行=开、流式=开、内省=开、调试=关。

---

## 七、多 VM 实例 + 用户代码多线程

- **多 VM 实例**：每并发路径一个轻量 VM 实例（完全隔离，留出全局可见只读数据），内核协调器管理生命周期，经 Channel 协调。
- **用户代码多线程**：`task = spawn(fn)` 显式任务句柄（join/cancel），供实时 UI/输出刷新。
- 复用现有 `spawn_isolated` 多引擎机制，升级为"同进程多线程多 VM"。
- 跨引擎（隔离运行）保持现有文件/序列化机制，不混用。

---

## 八、编译器改造（用户点破的盲点）

- 现状：57 个 AST 节点，仅 `IbAwaitExpr` 并发相关；44 个 dispatch handler；序列化不处理线程/任务。
- 需新增：`spawn`/`join`/`task`/`chan`/`signal`/`slot` AST 节点 + parser 语法 + 4 阶段语义 + dispatch + 序列化。
- **关键决策**：并发任务为运行时瞬态，不进入持久化状态（save_state/load_state）。

---

## 九、明确排除

- 跨进程 / CPU 并行（性能瓶颈在 IBCI 包装，非 CPU 并发）。
- 跨引擎通信（隔离运行是自我进化窗口，现阶段仅维护 + 同步演进）。
