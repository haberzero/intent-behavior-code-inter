# tasks_docs 治理章程

> 本文档规定 `tasks_docs/` 任务控制体系的**治理模式与书写模式**——每个文档的
> 职责、生命周期与红线；各文档的具体书写模板固定在该文档自身尾部。
> 全部任务控制文档必须遵守本章程。
> 本文档本身为章程（meta 文档），不承载具体任务内容。
>
> **书写要求**：修改本章程必须按本文尾部「书写模式」模板与格式书写，保持一致。

## 一、定位与边界

- `tasks_docs/` 是 IBCI 的**任务控制与决策记录体系**，面向项目维护者（含 AI
  智能体）与外界查阅者。
- 与 `docs/`（人类技术手册）分工：`docs/` 描述**系统是什么**（当前事实）；
  `tasks_docs/` 描述**项目在做什么、为什么、往哪去**（过程与规划）。
- 与 `git` 分工：历史与过程细节由 git 承载；任务控制文档只保留**当前有效**
  与**长期约束力**的内容。**不保留已完成条目的历史叙述**（git 可追溯）。

## 二、文档清单（单点真理）

| 文档 | 职责 | 更新时机 | 生命周期 |
|------|------|----------|----------|
| `GOVERNANCE.md` | 本章程：治理模式 + 书写模板索引 + 红线 | 治理规则变化时 | 常驻 |
| `NEXT_STEPS.md` | 当前最紧要主线 + 工作模式定论 + 下一步候选 | 主线变更时 | 常驻 |
| `PENDING_TASKS.md` | 远期任务正式清单（含搁置/封存/愿景） | 新任务/状态变化时 | 常驻 |
| `HANDOFF.md` | 固定化工作内容 + 动态交接状态 | session 交接时 | 常驻 |
| `WORKLOG.md` | 关键用户裁定 + 长期约束原则 | 决策发生时 | 常驻（只保留长期约束力内容） |
| `trials/` | 试用套件资产（用例/工具链/记录） | 试用时 | 测试资产（独立治理） |

**单点真理**：同一事实只在一个文档维护。任务状态以 `PENDING_TASKS.md` 为准；
主线状态以 `NEXT_STEPS.md` 为准；固定化工作原则以 `HANDOFF.md` §一为准。

## 三、书写模式（模板归属：各文档自身尾部）

各任务控制文档的**书写模板唯一权威 = 该文档自身尾部「书写模式」小节**（文档自描述）：

| 文档 | 尾部模板内容 |
|------|--------------|
| `PENDING_TASKS.md` | 条目编号 / 域分类 / PT 条目与 VISION 条目模板 / 字段规则 / 概览表维护 |
| `NEXT_STEPS.md` | 文档结构（含工作模式定论）/ 主线状态格式 / 维护规则 |
| `WORKLOG.md` | 文档结构 / 裁定表格模板 / 重大方向决策记录格式 |
| `HANDOFF.md` | 文档结构 / 分区规则 / 条目格式 / 维护规则 |
| `GOVERNANCE.md` | 本文档尾部「书写模式」（章程自身模板） |

**体系级书写通则**（适用于全部任务控制文档，各文档尾部模板不得违反）：

- 状态值域：`active`（活跃）/ `shelved`（搁置）/ `sealed`（封存）/ `done`（完成）；
  优先级 P0 > P1 > P2 > P3（维度：架构健康性 > 易用性 > 长远收益）。
- **不出现日期戳**；记录类文档（WORKLOG、trials 记录册）如需标注时间用 `YYYY-MM-DD`；
  **不冻结测试数字**（以实跑为准）。
- **不保留已完成历史叙述**（git 承载）；不复制 `docs/` 技术正文（单点真理）。
- 引用一律用仓库相对路径指针。

## 四、生命周期规则

| 阶段 | 规则 |
|------|------|
| 新建任务 | 复杂任务先写临时文档 `tasks_docs/_<task>.md`（设计/计划）；简单任务直接登记 PENDING_TASKS |
| 推进中 | 设计/决策记录在临时文档或 WORKLOG；状态同步 NEXT_STEPS/PENDING_TASKS |
| 完成 | 临时文档**必须删除**（git 承载历史）；PENDING_TASKS 条目标 done（或移除）；NEXT_STEPS 更新当前状态 |
| 搁置 | PENDING_TASKS 标 shelved + 搁置原因 |
| 封存 | PENDING_TASKS 标 sealed（恢复需显式解封评估） |

## 五、红线

- **不冻结测试数字**：基线以实跑为准（`python -m pytest tests/`）。
- **不保留已完成历史**：已完成条目的详细叙述属于 git。
- **无日期戳/无历史记录**：非记录类文档不出现日期戳与历史叙述（历史决策/缺陷/日志/基线），
  只描述当前状态；记录类文档（WORKLOG、trials 记录册）除外。
- **不复制 docs/ 内容**：技术事实引用 docs/ 指针，不复制正文（单点真理）。
- **不留半拆除状态**：删除/归档必须彻底（连同引用一并清理）。
- **临时文档禁止长期留存**：`_` 前缀文档完成即删，经用户确认后清理。

## 附、书写模式（本文档专用模板，书写必须参照）

> 本节是本章程自身的**唯一权威书写模板**（模板归属 = 文档自身）。
> 修改本章程一律按下列结构与格式书写。

### 1. 文档结构

```
# tasks_docs 治理章程
定位段（章程定位：治理模式 + 书写模板归属 + 生命周期 + 红线）
一、定位与边界（tasks_docs 与 docs/、git 的分工）
二、文档清单（单点真理：文档 × 职责 × 更新时机 × 生命周期）
三、书写模式（各文档尾部模板索引 + 体系级书写通则）
四、生命周期规则（新建/推进中/完成/搁置/封存）
五、红线
```

### 2. 章节规则

| 章节 | 规则 |
|------|------|
| 一 定位与边界 | 只写体系分工，不承载具体任务内容 |
| 二 文档清单 | 表格行 = 文档 × 职责 × 更新时机 × 生命周期；新增任务控制文档必须先在此登记 |
| 三 书写模式 | **只做索引与通则**；具体模板固定在各文档尾部（模板归属 = 文档自身），此处不复制模板正文 |
| 四 生命周期 | 表格：阶段 × 规则；规则必须可执行、无歧义 |
| 五 红线 | 每条一行"禁止 + 原因/替代"；新增红线需用户裁定或体系级问题驱动 |

### 3. 维护规则

- 章程只在**治理规则变化**时更新；一次只改一个治理点，随改随记（git 承载）。
- 某文档的书写模板变更时，改**该文档尾部**，不在此处复制；本章程只更新索引描述。
- 体系级通则（状态值域/优先级/日期规范/单点真理）变更时，检查全部文档尾部模板是否
  同步（治理一致性门）。
