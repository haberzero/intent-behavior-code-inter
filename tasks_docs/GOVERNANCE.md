# tasks_docs 治理章程

> 本文档规定 `tasks_docs/` 任务控制体系的**治理模式与书写模式**——每个文档的
> 职责、结构模板、生命周期与红线。全部任务控制文档必须遵守本章程。
> 本文档本身为章程（meta 文档），不承载具体任务内容。

## 一、定位与边界

- `tasks_docs/` 是 IBCI 的**任务控制与决策记录体系**，面向项目维护者（含 AI
  智能体）与外界查阅者。
- 与 `docs/`（人类技术手册）分工：`docs/` 描述**系统是什么**（当前事实）；
  `tasks_docs/` 描述**项目在做什么、为什么、往哪去**（过程与规划）。
- 与 `git` 分工：历史与过程细节由 git 承载；任务控制文档只保留**当前有效**
  与**长期约束力**的内容。**不保留已完成条目的历史叙述**（git 可追溯）。

## 二、文档清单（单点真理）

| 文档 | 职责 | 更新时机 | 生命周期 |
|------|------|----------|----------|
| `GOVERNANCE.md` | 本章程：治理模式 + 书写模板 + 红线 | 治理规则变化时 | 常驻 |
| `NEXT_STEPS.md` | 当前最紧要主线 + 最近完成摘要 | 主线推进/完成时 | 常驻 |
| `PENDING_TASKS.md` | 远期任务正式清单（含搁置/封存/愿景） | 新任务/状态变化时 | 常驻 |
| `HANDOFF.md` | 固定化工作内容 + 动态交接状态 | session 交接时 | 常驻 |
| `WORKLOG.md` | 关键用户裁定 + 长期约束原则 | 决策发生时 | 常驻（只保留长期约束力内容） |
| `trials/` | 试用套件资产（用例/工具链/记录） | 试用时 | 测试资产（独立治理） |

**单点真理**：同一事实只在一个文档维护。任务状态以 `PENDING_TASKS.md` 为准；
主线状态以 `NEXT_STEPS.md` 为准；固定化工作原则以 `HANDOFF.md` §一为准。

## 三、书写模式（八股模板）

### 3.1 PENDING_TASKS 条目模板

```markdown
### PT-XXX 任务名（短名词短语）

- **域**：FEAT（功能）/ DEBT（技术债）/ AUDIT（审计）/ DOC（文档）/
  TEST（测试）/ DECIDE（决策）/ SEALED（封存）
- **状态**：active（活跃）/ shelved（搁置）/ sealed（封存）/ done（完成）
- **优先级**：P0 / P1 / P2 / P3（维度：架构健康性 > 易用性 > 长远收益）
- **动机**：为什么想实现（用户驱动 / 架构统一 / 宣发需求）
- **成因**：问题从哪来（历史妥协 / 演进缺口 / 缺陷暴露）
- **搁置原因**：（shelved 时必填）为什么停止
- **当前理解**：现状边界 + 已确认方向（如有）
- **关联**：相关文档/代码/其他任务（指针，不复制内容）
```

### 3.2 NEXT_STEPS 结构模板

```
# NEXT_STEPS — 当前最紧要项
定位段（本文件只记录当前最紧要、可立即开工的下一步；长期规划见 PENDING_TASKS）
🔴 当前主线（1 段：任务 + 阶段 + 验收门 + 交接指针）
✅ 最近完成（1-3 条摘要，每条：时间 + 内容一句话 + 验证结果一句话）
（历史完成条目从本文件移除——git 承载）
```

### 3.3 WORKLOG 条目模板

```
| **标题（时间，分支/commit，验证结果）** | 关键裁定/决策 + 变化前后摘要（实现+测试+文档）|
```

只保留**仍有长期约束力的关键用户裁定**与**重大决策的变化前后**；例行完成记录
由 commit 消息承载，不写入 WORKLOG。

### 3.4 HANDOFF 结构

- **§一 固定化内容**（长期不变）：工作流程指针、用户裁定与原则、goal 配置习惯、
  任务控制文档结构指针。
- **§二 动态状态**（随任务更新）：当前任务/下一阶段、近期完成摘要。

## 四、生命周期规则

| 阶段 | 规则 |
|------|------|
| 新建任务 | 复杂任务先写临时文档 `tasks_docs/_<task>.md`（设计/计划）；简单任务直接登记 PENDING_TASKS |
| 推进中 | 设计/决策记录在临时文档或 WORKLOG；状态同步 NEXT_STEPS/PENDING_TASKS |
| 完成 | 临时文档**必须删除**（git 承载历史）；PENDING_TASKS 条目标 done（或移除）；NEXT_STEPS 记摘要 |
| 搁置 | PENDING_TASKS 标 shelved + 搁置原因 |
| 封存 | PENDING_TASKS 标 sealed（恢复需显式解封评估） |

## 五、红线

- **不冻结测试数字**：基线以实跑为准（`python -m pytest tests/`）。
- **不保留已完成历史**：已完成条目的详细叙述属于 git。
- **不复制 docs/ 内容**：技术事实引用 docs/ 指针，不复制正文（单点真理）。
- **不留半拆除状态**：删除/归档必须彻底（连同引用一并清理）。
- **临时文档禁止长期留存**：`_` 前缀文档完成即删，经用户确认后清理。
