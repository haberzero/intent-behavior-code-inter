## 一、用户的核心关切

**反射机制滥用只是表象，底层契约未显式化才是根源。**

> 用户原话（复述要点）："我启动这个关于反射的分析和修理的相关工作绝不只是为了停止在表面，我就是期望通过 hasattr 等特征点，找出那些以前被隐藏起来的架构缺陷并且给予处理。"
> "我不太在意修复的工作量问题，哪怕有些工作更困难，但我们也应该选择那些更正确、架构更合理、可维护性等各方面都更好的设计。"

因此：**每个反射/异常/字符串/私有属性特征点，都要追问"它为什么存在？掩盖了什么机制缺陷？"，修复 = 消除缺陷根因，而非替换写法。** 这已被多轮验证：
- hasattr → orchestrator 注入死参数链（组 6）
- hasattr → late-hydrate 空壳生命周期钩子（组 7）
- hasattr → 能力注册双通道 + import* 运行时损坏（组 2）
- 异常字符串嗅探 → 异常缺结构化错误码（组 3/8）
- 私有属性注入 → 模块契约未显式化（组 2）

## 二、用户的工作习惯（硬规则）

1. **不做形式修复，只做根治**：每个点追问"原防御在防什么？被防场景现在怎样？"，用禁用验证/实测确认，而非机械删除。
2. **无妥协、无历史包袱、不计工作量**：选择更正确、架构更合理、可维护性更好的设计，哪怕更困难；不因"已有代码在仓库里"而豁免。
3. **功能逻辑统一化**：同类机制收敛单一入口/单一契约，消除双通道、双写真相、隐式约定。
4. **协议驱动 + 显式优于隐式**：能力/类型通过协议声明，不靠反射/私有属性探测；契约显式传递而非字符串/私有属性约定。
5. **证据驱动**：每个"死代码/冗余"判断用禁用验证/实测确认，不靠静态推演下结论（**组 6 教训**：误判时序导致把必需代码当死代码）。
6. **分层架构遵守**：依赖规则（kernel→base 单向，runtime→kernel），objects/kernel 不能引 runtime/interpreter。
7. **自反馈验证**：每批改动全量 `python -m pytest tests/` + 残留扫描零回归。

## 三、用户的质询模式（如何被"拷问"）

用户会主动质询，典型模式（务必诚实、证据化应对）：

1. **"这部分内容是合理的？还是某种更隐晦的深层架构缺陷？"**——当你用了反射/保留了什么"合理"代码时，用户会深挖它是不是症状。**应对**：主动深查根因，区分"合理机制"（协议/隔离/设计内反射）vs"症状"（鸭子类型判别、双通道、隐式契约），给出证据判定。例：组 2 后复核 hasattr 时，深查出 `IbModule.scope` 鸭子类型判别 + 判定 `_ibci_registry_id` 是合理隔离机制。

2. **"你可能过于关注单一特征"**——当你聚焦单一模式时，用户会提示扩大视野。**应对**：启动独立 subagent 从其他视角复核，避免自己的盲点。例：过度聚焦 hasattr → 非 hasattr 反射面重复核（组 8），发现异常字符串嗅探、能力名裸字符串、签名静默降级等。

3. **"我不在意工作量，选更正确、更架构合理、可维护性更好的设计"**——用户拒绝最小修复，要求根治。**应对**：方案设计时主动选协议化/统一化方案，即使改动大（例：IbModule.scope 协议化而非改 isinstance）。

4. **"复述我的工作习惯，再判断合理修复模式"**——用户要求先对齐原则再动手。**应对**：先复述用户原则（根治/无妥协/统一化/协议驱动/证据驱动），再基于原则选方案。

5. **发现误判时**——用户会严厉指出（如组 6 把必需代码当死代码删错）。**应对**：诚实承认误判、用证据纠错、恢复代码、总结教训，绝不辩解。

## 四、用户的核心判定基准（写进方案前对照）

| 模式 | 定性 | 处置 |
|---|---|---|
| 协议声明能力、调用方按协议分派 | 职责分离合法反射 | 保留 |
| 外部插件固定命名（`__ibcext_vtable__` 等）、动态导入 | 设计内反射（§7.3 文档化） | 保留 |
| 显式 vtable 分派表（VM `_dispatch`） | 正面模式 | 保留 |
| `hasattr` 探测已知类型未声明方法 | 协议声明滞后 | 并入协议 |
| 鸭子类型判别已知两形态 | 类型契约缺失 | 协议化（如 `IModuleScope`） |
| 私有属性注入契约（`_ibci_vtable`/`_ibci_whitelist`） | 隐式契约 | 显式承载（interop contract） |
| 异常字符串嗅探分类 | 反射变体 | 结构化错误码 |
| 跨层裸字符串契约（能力名） | 字面量散落 | 常量/登记 |
| 静默兜底掩盖错误 | 违 fail-fast | 改 fail-fast |
| 对象身份标记（`_ibci_registry_id` 跨 engine 隔离） | 合理机制 | 保留（对象身份须挂对象上） |
