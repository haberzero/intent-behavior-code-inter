# IBCI 职责重定位：编排平台 + 统一表达（2026-09-11 用户探讨裁定）

> 本文件 = IBCI 在 Rust/Python/tilelang/生态 体系中的职责裁定（用户探讨后认可）。
> 修正 R0 架构路线中"计算基板 = 内核实现标量/AVX"的偏差——内核不做数学库，
> 不做外部语言解释器。设计阶段文档，落地后收敛入 docs/。

---

## 一、核心裁定（一句话）

**IBCI = 一个"交互平台 + 统一表达面"**：它表达数据结构、LLM 调用行为、embedding
调用行为、世界模型建模、并行计算操作、宿主生态交互，并**编排**这些交互——但它
**不实现、不执行、不接管**外部引擎的内部。

IBCI **不是**"执行 Python / tilelang / AVX 的运行时"——它是这些能力的**统一表达与
编排平台**。外部引擎（LLM provider / numpy / torch / tilelang / Python 生态）各司
其职，Rust 内核保持干净、可维护、GIL-free。

## 二、三层结构（修正版）

```
┌───────────────────────────────────────────────────────────────┐
│ IBCI 统一表达面（语言）                                         │
│   数据结构（scalar/容器/quoted/Tensor）                        │
│   LLM 调用行为（15 节点宿主面）      embedding 调用行为          │
│   世界模型建模（KB 知识图谱）       并行计算操作（声明式）       │
│   宿主生态交互（HOST-EXT）                                     │
├───────────────────────────────────────────────────────────────┤
│ Rust 内核 = 编排引擎（不是数学库，不是外部语言解释器）           │
│   执行 IBCI 自身的编排语义（控制流/数据/调用编排）               │
│   核心执行 GIL-free（外部调用只在边界短暂取 GIL）               │
│   经统一协议调度外部引擎：LLM 宿主 / 计算引擎 / 生态网关         │
├───────────────────────────────────────────────────────────────┤
│ 外部引擎（被编排的执行者——内核不触碰其内部）                    │
│   LLM provider（Python 宿主）                                  │
│   并行计算：numpy / torch / tilelang（插件层引擎）              │
│   Python 生态（HOST-EXT 网关）                                 │
│   SIMD/AVX/GPU = 这些引擎内部的事（或用户 Rust 插件）           │
└───────────────────────────────────────────────────────────────┘
```

## 三、三条硬边界（结构性统一的关键）

1. **内核不实现外部引擎的"内部数学"**——不做 SIMD 库、不解释 tilelang、不实现
   LLM。AVX/GPU = 外部引擎内部（numpy/torch 自带 SIMD）或用户 Rust 插件（④层）
   的事。
2. **内核不执行外来代码**——不执行 Python、不传 tilelang 源码。IBCI 只**编排
   调用**（函数句柄/协议调用），外部代码留在外部。
3. **内核核心 GIL-free**——编排语义的执行永不持 GIL；只有"与 Python 宿主交互"
   的边界才短暂取 GIL（编排的本质成本，非内核被锁死）。

## 四、扩展分层（按与内核的距离——用户确认）

| 层 | 内容 | 进入成本 | 场景 |
|----|------|---------|------|
| ① 语言面 | IBCI 代码（Rust 内核执行） | 零 | 用户逻辑默认归宿（DSL 定位） |
| ② 宿主面 | Python 生态接入（HOST-EXT 协议，已落地） | typed 值转换 + GIL 边界 | LLM SDK/numpy/torch/网络/文件 |
| ③ 计算面 | Tensor 统一数据形态 + **计算编排协议** | 缓冲交换 | 并行计算操作编排（numpy/torch/tilelang 引擎） |
| ④ 原生面 | Rust 插件（ibci-sdk crate + cdylib 插件 ABI） | 编译链 | 手写 SIMD/自定义热循环（罕见） |

**扩展层越深进入成本越高 = 设计意图**（不是缺陷）：90% 需求被 ①③ 覆盖。

## 五、关键场景裁定

- **tilelang**：插件层外部引擎。用户**正常书写 tilelang**（自己工具链），产出 =
  编译内核/函数句柄；IBCI 经计算编排协议调用句柄（输入/输出 = Tensor 缓冲），
  结果进 IBCI 表达（世界模型查询/LLM 调用/后续编排）。**IBCI 不接管书写、不传
  源码**——tilelang 管"怎么算"，IBCI 管"算什么、算完怎么用"。
- **AVX/GPU**：不进核心执行层。内核只做**并行计算操作的编排**（声明式"做什么"
  → 调度已注册引擎）；标量回退 = 正确性/可移植性兜底（可选），非性能路径。
- **Python 生态**：网关（HOST-EXT）而非执行。"让 IBCI 执行 Python 代码" = 明确
  非目标（GIL 锁死 + 职责错位）。
- **numpy/torch**：经 Tensor 缓冲互转（`to_numpy`/`from_numpy` 宿主模块 + 
  torch 桥接），零拷贝缓冲级交换，非逐值包装。
- **vector → 1D Tensor**：统一数据形态（与 numpy/torch/tile 交互的交换格式）。

## 六、结构性统一方案（IBCI/Python/Rust 三者）

- **权威层**：语言契约（公理 + 语义错误集）单一权威源；值模型 = Rust 内核 typed
  值（P2 通道形态：{kind, value}）。
- **投影层**：Rust 原生（同一份）；Python = typed 值通道投影（已实现）；外部插件
  = 同一 typed 契约（ibci-sdk 类型 = 内核值模型类型）。
- **统一规则**：① 跨边界 = 经 typed 契约（P1-P5），禁 ad-hoc 包装/解包；② 公理/
  数据模式 = 契约权威（消除"Python 语义转录"——实现投影，不转录语义）；③ 数据
  形态统一 = Tensor（缓冲级交换）。
- **消除**：Python 对象模型（IbObject 体系）逐步收敛为"typed 值的薄投影"，不保留
  独立语义实现（差分机制 ⑦ 终点退场后 Python 参考内核退役）。

## 七、对路线的影响（修正）

| 项 | 影响 |
|----|------|
| R1-R4（协议化/值通道/错误契约/HOST-EXT/pip） | 不受影响——正是"编排平台"的地基 |
| R5 计算基板 | **重定义**：不做 SIMD 实现；= Tensor 值 + 计算编排协议（引擎注册/调度/缓冲交换） |
| Rust 插件（④ R6） | 保留为手写 SIMD/自定义内核归宿（不在内核核心） |
| 内核体量 | 更小、更纯（编排 + 表达，不背数学库）——合用户点⑦ |
