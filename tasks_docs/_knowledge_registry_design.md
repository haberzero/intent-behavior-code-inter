> 日期：2026-09-07（free-explore）。性质：**设计阶段文档**（子系统级，与
> `_embedding_design.md` 同级严肃度）。本文件取代 `_n2_answer_registry.md`

> **用户裁定（2026-09-07，本文档的设计前提）**：
> ① 本机制**不以 `ai` 模块为载体**——`ai` 保持模型 I/O 面纯粹性，不得被知识存储面污染；
> ② **行为描述语句（`@~...~`）的语义 = 针对 LLM 的调用行为，这是语义不变量**——
>    知识存储的隐形判断（引擎路由/查表短路）**永远不得**进入 LLM 语句语义；
> ③ 本机制是**语言学层面**的问题（知识存储机制 ≈ 数据库层面的机制），要求与
>    embedding（PT-FEAT-16）同级的系统设计：**怎么建模 / 怎么成体系实现 / 怎么与既有
>    组件有机交互 / 放在什么地位 / 怎么合理使用 / 怎么设计易用性**；
> ④ "绝不是放进 ai 组件"——LLM 调用机制的一致性与纯粹性是硬约束。

## 一、地位：语言自动机的知识层（D 纸带），一等子系统

### 1.1 使命定位

IBCI 使命 = 稳定可靠的语言自动机服务。灰盒架构三层分工（结构层确定性 / 内容层神经 /
接口类型化）中，**"验证过的知识从神经层毕业到确定性层"是使命的核心动力学**
（试用方 172 轮实证："用得越久越确定"；e25 机制：词典外新词 → LLM 提案 → 确定性裁判
逐证据重验 → 一致才提交 → 后续 0 次调用）。该机制目前只能写在外部 Python 里——
N2 的使命 = 让它成为**语言级机制**：机器持有的知识是**类型化、门控、可审计**的。

### 1.2 系统地位（本设计的核心裁定）

| 支柱 | 纸带 | 职责 | 载体 |
|------|------|------|------|
| 意图（intent 体系） | M 纸带 | 认知作用域（改写解释） | 既有（值类型 intent_context + 语句级 @/@+ 等） |
| 模型 I/O（ai 模块） | — | LLM 调用 / embedding 调用（纯模型交互） | 既有 ai（Q1 裁定后 + ai.embed） |
| **知识（本子系统）** | **D 纸带** | **已验证知识的持有/查询/更正/审计** | **新建：一等内置值类型（地位 = dict/vector 同层）** |

- 定位类比（用户提示）：**自动机的知识库（in-language knowledge database）**——
  持久（save_state）、结构化（类型化条目）、门控（验证谓词）、可审计（append-only
  事件流）、可查询（显式键）。
- **语义不变量（硬，写入设计文档与语言手册）**：
  1. `@~...~` 行为描述语句 = **LLM 调用**，语义不因本子系统改变；本子系统**不提供**
     任何"查表命中则跳过 LLM"的语句内隐式路由（原 Q3 方案 b **原则性否决**，非挂起）；
  2. 一切知识操作 = **显式程序操作**（普通值方法调用，代码可见、可审计、可测试）；
  3. "先查知识库再决定是否调 LLM"是**用户的控制流**（显式 if/else），不是引擎的隐式
     行为——模式本身由文档与试用沉淀为惯用法（canonical idiom）。

## 二、建模：一等内置值类型（命名待确认）

### 2.1 类型形态

- **一等内置值类型**（公理层注册，与 `vector`（PT-FEAT-16 批②）、`intent_context`
  同层机制）：可构造（`k = knowledge()`，intent_context() 构造先例）、可多实例
  （程序持有多个知识库，如 dict）、可传参/可存变量/可进 save_state。
- **不是**引擎全局隐藏状态（旧版 Q7 的"引擎级状态 + save_state 默认纳入"方案
  **作废**——隐藏状态违反"状态即值"的 IBCI 设计语言；显式值对象 + 既有 save_state
  值语义 = 零新增持久化面）。

### 2.2 条目内部模型

```
键（str，显式）→ 条目 {
  value:   深克隆冻结快照（store 时深克隆；取回时亦深克隆——防 P10 引用陷阱污染审计）
  check:   登记时的验证谓词名/引用（审计"经谁验证"）
  events:  append-only 事件流 [ {seq, kind: store|amend, value, reason} ]
           （seq = 引擎事件序号，单调，可复现——非墙钟）
}
```

### 2.3 方法面（命名待确认；容器约定与 dict 同构 + 铁律额外项）

| 方法 | 语义 | 铁律/纪律 |
|------|------|----------|
| `k.store(key, value, check)` | 登记（首次写入） | **引擎求值 `check(value)`**：假 = fail-fast 错误（"未过验证门，拒绝登记"）；`check` 体内含 LLM 调用 = **编译期 SEM 错误**（新增语义错误，P0-1 消费项）；`check` 为**不透明 fn 值**（静态无法判定其确定性）= **同样 SEM 错误**（fail-fast：不纯度不可证明即拒绝，不做运行期探测兜底）；键已存在 = 错误（"登记"与"更正"机器强制区分，更正走 amend） |
| `k.get(key)` | 查询当前值 | 未登记 → null（合法状态非错误）；**返回深克隆快照**（修改取回值不污染知识库） |
| `k.amend(key, new_value, reason)` | 更正 | reason **强制非空**（空 = 错误）；新值**再过 check 门**（防更正通道变无门控写口）；append-only（原值保留 events，当前值指针切换） |
| `k.history(key)` | 审计 | 事件序列 list（{seq, kind, value, reason}）；未登记 → 空 list |
| `k.keys()` / `k.len()` | 枚举/计数 | dict 容器约定同构 |

### 2.4 类型语义要点

- 知识库对象本身 = **可变值对象**（如 dict：引用语义、共享、save_state 值语义）；
  条目值 = **冻结快照**（深克隆两次：store 入时 + get 出时）——"知识库可变，知识不可变"。
- 值语义（与 vector 的 C5 判别同域但不同选择：知识库是**引用语义容器**（同 dict），
  条目值是**值语义快照**——混合语义在类型文档中显式声明）。

## 三、成体系实现（分层；机制同构 = vector 批② 同一链）

| 层 | 内容 | 纪律 |
|----|------|------|
| 公理层 | 类型注册（值类型注册表 + 克隆/序列化接入 + 诊断码域） | 触语义错误集 → **全量 pytest 评估门**（与 vector 批②同级） |
| runtime 对象层 | 实现类（命名随类型定）+ 深克隆/序列化器集成（平铺池 + UID 侧表同构存储，试用方原话"不引入新存储范式"） | 与 IbDict/IbValue 既有机制同构 |
| 诊断层 | **独立诊断码域**（命名随类型定；EMB_ 先例：一等面有自己的域）+ 全部错误带 ibci 源行（P0-1 消费） | 15_diagnostics 域语义 |
| 文档层 | docs/ 语言子系统页（地位/语义不变量/条目模型/方法面/惯用法/边界） | doc-governance 流程；docs 只面向人类 |
| 试用层 | T 套件试用（**纯确定性子系统：mock 模式 = 真实模式**，无 LLM 依赖；验收 = 试用方 e25 机制改写 + fail-fast 判别 + save/load 保真 + 并发读） | trials/INDEX 纪律 |

## 四、与既有组件的有机交互（矩阵）

| 组件 | 交互设计 |
|------|---------|
| **intent / snapshot / lambda** | lambda/snapshot 捕获知识库值 = **深克隆**（该时刻的知识冻结副本——snapshot 语义天然正确）；知识库不参与意图注入（D/M 两纸带分离） |
| **ihost.save_state / load_state** | **自动**（值语义——知识库是变量，save/load 既有机制覆盖，零新持久化面）；试用方"跨会话越用越确定"即由此成立 |
| **ihost.run_isolated** | 传入隔离脚本的知识库 = 隔离副本（既有隔离语义） |
| **run_batch 并发** | 值语义：并行项**可读**（get/history/keys/len，GIL 单操作原子）；store/amend = **单逻辑步**（多字段写设计为原子 + 文档化"写归主流程"的惯例）；不做特殊并发协议（需要时按并发子系统纪律另设计） |
| **llmexcept** | 无交互（知识库不是 LLM；store 的 check 求值不含 LLM——编译期保证） |
| **overlay（用户覆层）** | 内置类型（同 dict），不在用户 overlay 范围 |
| **P0-1 诊断面** | check 含 LLM 的 SEM 错误 + 全部运行期错误**携带 ibci 源行**（P0-1 的直接消费项——队列排序"诊断面先行"的理由之一） |
| **P0-2 embedding** | **v1 无语义检索**（显式 str 键，不做"相似问题自动命中"）；M2（结构签名检索/模式匹配 few-shot，试用方 e31b 实证机制）= 依赖 embedding/检索面的**未来独立扩展**，不在本设计 |
| **mock / 测试** | 子系统纯确定性（无 LLM）→ mock 模式行为 = 真实行为；验收双轨（mock 断言 + 用户脚本 live 验证）天然成立 |
| **json / fs** | 无交互（知识库不读 JSON 文件、不写 fs——持久化 = save_state 一条路，单源） |

## 五、合理使用与易用性设计

### 5.1 惯用法（canonical idiom，文档 + 试用沉淀）

```ibci
# 先查知识库（显式控制流——引擎不隐藏任何判断）
opt stored = kb.get("term:修炼")
if stored.is_some():
    str use = stored.unwrap()                 # 命中：0 次 LLM 调用（用户代码显式可见）
else:
    str answer = @~ 在修真世界观中，"修炼" 指什么？ ~   # 未命中：纯 LLM 调用（语义不变）
    bool ok = answer.len() > 0 and answer.contains("修炼")  # 确定性验证（用户的世界模型）
    if ok:
        kb.store("term:修炼", answer, check)  # 过门才登记（门 = 引擎强制）
```

### 5.2 易用性设计点

1. **零新语法**：类型 + 方法 + 既有控制流（用户不学新语句）；
2. **命名平实**（无黑话）：类型与方法名待 §六 确认；
3. **错误可定位**：全部失败面 fail-fast + 诊断码 + ibci 源行（P0-1 消费）——
   "拒绝登记/键已存在/理由为空/check 不纯"每类错误一句话可懂；
4. **容器直觉**：get/keys/len 与 dict 同形（用户已有的容器心智直接迁移）；
5. **持久化透明**：save_state 一行覆盖（无额外持久化 API 要学）；
6. **审计自含**：history() 即完整审计链（seq 可复现、reason 强制、原值保留）。

### 5.3 边界（不做什么，防过度设计）

- 无引擎内隐式路由（语义不变量 §1.2——**原则性否决**）；
- 无语义/相似自动命中（v1 显式键；M2 归未来 + 依赖 P0-2）；
- 无内置持久化文件面（save_state 即持久化，单源）；
- 无跨进程/跨引擎共享（脚本间传递 = 值传递，ihost 既有语义）;
- 无墙钟（确定性序号）；无刚性条目标记（v1 全部可更正，"刚性"= 用户领域纪律）；
- 无引擎全局隐藏状态（一切知识库 = 显式值对象）。
