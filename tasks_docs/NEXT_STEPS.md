## 附、书写模式（本文档专用模板，书写必须参照）

> 本节是本文档书写的**唯一权威模板**（模板归属 = 文档自身；`GOVERNANCE.md`
> §三 仅做索引）。更新本文档一律按下列结构与格式书写。

### 1. 文档结构

```
# NEXT_STEPS — 当前最紧要项
定位段（只记录当前最紧要、可立即开工的下一步；长期规划见 PENDING_TASKS）
🔴 当前主线（1 段：任务 + 阶段表 + 验收门 + 交接指针）
**下一步候选**（等待用户指示的候选项，按序编号）
✅ 最近完成（1-3 条摘要）
（历史完成条目从本文件移除——git 承载）
```

### 2. 阶段表格式（当前主线为多阶段任务时）

| 列 | 内容 |
|----|------|
| 阶段 | 阶段代号 + 一句话主题 |
| 状态 | ✅ 完成 / 🔄 进行中 / ⏳ 待用户 / ❌ 阻塞 |
| 内容 | 本阶段做了什么（2-4 项要点） |
| 验证 | 放行证据（全量 pytest + 复核 + 复跑，不冻结数字） |

### 3. 最近完成条目格式

每条一行摘要：**时间 + 任务名（一句话）**：内容一句话 + 验证结果一句话。
- 时间用日期（YYYY-MM-DD），不写具体时刻；
- 验证结果用实跑描述（"全量 pytest 零回归"），**不冻结具体数字**；
- 最多保留最近 1-3 条；更早的由 git 承载。

### 4. 维护规则

- 主线变更时更新"当前主线"与"下一步候选"；阶段完成时更新阶段表状态并追加摘要。
- 待用户确认项只在此标注；不建独立章节。
- 引用其它任务控制文档用相对路径指针，不复制正文。
