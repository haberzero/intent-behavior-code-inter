# 06 交接文档 — 书写规范

## 职责

让**下一个 session（或下一个智能体）能够完整接续**当前工作状态，不丢失任何关键信息。是 session 边界的状态快照。

## 要确保什么（交接完整性清单）

下一 session 拿到交接文档后，必须能回答：

1. **现在是什么状态？**——当前工作状态（主线/分支/基线）。
2. **做了什么？**——已完成（含 commit 引用）。
3. **接下来做什么？**——下一步 + 可执行任务清单（顺序、验收标准）。
4. **有哪些工作原则必须遵守？**——自主运行配置（授权原则、goal 模板、上报阈值、交付纪律、分支政策、日志纪律）。
5. **有哪些关键约束？**——交付/决策/文档治理/工作模式定论/非目标。
6. **待决项是什么？**——未决事项 + 待清理项。
7. **完整 goal 配置模板**——可直接复制的 goal objective。

## 必备章节

1. **头部**：临时交接声明（交接完成后删除）、当前状态一句话、分支、测试基线。
2. **当前工作状态**：主线、下一步、分支、基线。
3. **已完成**：本次会话 + 历史，含 commit 引用。
4. **自主运行配置**（核心）：
   - 授权原则（自主推进/决策纪律/交付纪律/重构授权/分支政策/工作流/模式定论/文档治理/日志纪律）
   - **goal objective 模板**（可直接复制）
   - 支线任务清单
   - 上报阈值
5. **当前工作状态详情**：最重要任务的具体决策、进度、下一步。
6. **关键约束与原则**：必须遵守的硬规则。
7. **待决项 / 待清理**：未决 + 交接后删除本文件。

## 关键纪律

- **goal objective 模板必须完整**：授权原则全文纳入，下一 session 直接复制。
- **交接后删除**：完成交接后经确认删除本文件（状态由 git 承载）。
- **不复制已有文档**：指向决策记录/任务控制文档，不重述其内容。
- **反映真实状态**：交接时核对 NEXT_STEPS/PENDING_TASKS/决策记录是否同步，未同步先更新。
- **可执行**：下一步给出"从哪个任务哪个动作开始"。
