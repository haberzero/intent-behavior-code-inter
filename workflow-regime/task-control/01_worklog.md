# 01 WORKLOG — 工作日志书写规范

## 职责

记录**所有自主决策、质询分析、方案取舍、变化前后（实现+测试+文档）**。是决策的沉淀库，供未来追溯。

## 何时写

- 任何自主决策做出时
- 任何方案取舍确定时
- 任何质询/分析得出结论时
- 任何实现/测试/文档变更完成时

## 怎么写

每个条目包含：

1. **决策记录**（结构）：
   - 决策内容
   - 落点（涉及的文件/模块）
   - 依据（为什么这么选）
   - 变化前后（实现+测试+文档分别的前后状态）

2. **每会话一条**：以会话为段落，标注日期。

## 核心纪律

- **"只记录，不断决"**：能自主决定的记录决定并推进，不断等用户；只有确实无法决定的才标记"待决"并上报。
- **详尽**：宁可多写，不省略推理过程——未来追溯时推理过程与结论同等重要。
- **诚实记录教训**：包括错误的决策、被纠正的方向（如"提炼方向两次纠正"的教训）。
- **不跨文档复制**：决策记录段落可在 WORKLOG 或对应任务文档中；同一决策只在一个地方详述，其它地方只放指针。

## 结构示例

```
## 2026-XX-XX 会话 N：<主题>

### 决策记录
- **<决策名>**：内容 / 落点 / 依据 / 变化前后

### 变化前后
- 新增：<文件>（<职责>）
- 修改：<文件>（<改动>）
- 测试：<命令> = <计数> 零回归

### 待决
- <无法自主决断项>（给推荐 + 理由）
```
