# 05 临时任务文档 — 书写规范

## 职责

追踪**单个复杂任务的多修改单元**。是任务的工作簿：记录要改哪些文件、每个修改单元的状态、验证结果。

## 何时用

- 复杂任务（多文件、多阶段、跨 skill）
- 大规模整改 / 文档治理 / 代码审计
- 需要跨 session 或多批次推进的任务

## 怎么写

1. **命名**：下划线前缀 + 简短任务名（如 `_<task>.md`）。
2. **头部**：任务目标一句话、涉及范围。
3. **修改单元清单**（表格或列表）：
   - 单元描述 / 涉及文件 / 状态（待做/进行中/已完成）/ 验证
4. **验证记录**：每批改动后的测试结果。
5. **待决项**：无法自主决断的项。

## 生命周期（强制）

- **创建**：任务开始时创建。
- **推进**：每完成一个修改单元更新状态。
- **验证**：每批全量测试零回归。
- **删除**：任务完成、汇报后**经用户确认必须删除**。禁止保留已完成文档。
  - 理由：状态已由 git 承载；保留已完成文档会造成"过程产物长期滞留"。
  - 删除纪律适用：若确认要继续/推迟，明确标注后仍不长期留存。

## 与其它文档的分工

- 临时任务文档 = 单任务的**过程工作簿**。
- WORKLOG = 决策的**沉淀库**（跨任务）。
- 决策记录 = 重大方向的**权威依据**。
- 完成后的总结（变化前后、测试、后续技术债）并入 WORKLOG，临时文档删除。
