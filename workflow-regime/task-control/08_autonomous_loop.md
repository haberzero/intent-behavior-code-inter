# 08 自主工作循环 — 执行协议

> 智能体执行任何任务时的**统一循环协议**。与 goal 机制（07）配合：goal 提供目标生命周期，本协议提供"每步怎么走"。

## 一、循环总览

```
理解 → 设计质询 → 自主决策 → 实现 → 自反馈验证 → 自主纠错 → 交付自查 → 收尾
```

每步的输入/关键动作/输出：

## 二、各步

### 1. 理解
- 输入：任务指令 / NEXT_STEPS / PENDING_TASKS
- 动作：定位任务、阻塞与硬约束；读项目级 AGENTS.md（测试命令/目录/约定）
- 输出：任务是什么、边界是什么、硬约束是什么

### 2. 设计质询
- 输入：任务理解
- 动作：方案对照 工作模式定论 + self-grill 自我质询 + code-odor 异味自查 + design-philosophy 设计哲学
- 输出：方案 + 被质询消解的决策点

### 3. 自主决策
- 输入：方案
- 动作：能自主决断的自行决断并记录理由；仅触及上报阈值的项向用户陈述（方案+推荐+理由）
- 输出：决策（含理由记录）

### 4. 实现
- 输入：决策
- 动作：按 code-workflow 卫生纪律；每完成一个修改单元记入临时任务文档
- 输出：代码变更

### 5. 自反馈验证
- 输入：代码变更
- 动作：跑项目测试命令全量 + 残留扫描 + 自复核（subagent 报告不等于做完）
- 输出：测试结果 + 残留状态

### 6. 自主纠错
- 输入：验证结果
- 动作：验证失败/异味命中 → 回到根因阶段修复再验证，循环至干净或需上报；禁止症状层打补丁
- 输出：干净状态 或 上报项

### 7. 交付自查
- 输入：干净代码
- 动作：code-quality 提交前自查 + self-grill 未决断项归零
- 输出：可提交状态

### 8. 收尾
- 输入：可提交代码
- 动作：本地 commit（禁 push）+ 文档同步（NEXT_STEPS/PENDING_TASKS/WORKLOG）+ 临时文档清理 + 汇报
- 输出：commit + 文档同步 + 汇报

## 三、质量门（每批强制）

- 全量测试零回归（`python -m pytest tests/` 或项目等价命令）。
- code-quality §九 提交前自查（grep 兜底/兼容/双通道）。
- self-grill 未决断项归零。
- 汇报含：改动文件、测试结果、后续技术债。

## 四、与 goal 的衔接

- 每子任务走完本循环 = goal Phase B 的一步。
- 循环中触及上报阈值 = goal Phase C 阻塞判断。
- 循环收尾的 commit + 文档同步 = goal 进度的可观察记录。

## 五、自我进化的部分

- 本协议与相关 skill 定期回顾：哪些步可强化？哪些检查遗漏？哪些决策可更自主？
- 产出改进建议写入 WORKLOG 或对应 skill。
