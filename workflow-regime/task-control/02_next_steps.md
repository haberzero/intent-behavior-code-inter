# 02 NEXT_STEPS — 当前最紧要项书写规范

## 职责

记录**当前周期内最紧要、可立即开工的下一步**。是智能体开工时最先读的文档。

## 与其它文档的分工

- **NEXT_STEPS**：当前在做什么 + 下一步是什么（最紧要）。
- **PENDING_TASKS**：被阻塞/搁置但有价值的规划（NEXT_STEPS 不记阻塞项）。
- 阻塞/等前置项不写进 NEXT_STEPS，写进 PENDING_TASKS。

## 怎么写

1. **顶部锚点**：`最后更新` 日期 + 当前主线一句话（如"线程对象模型方向修正已授权未实现"）。
2. **工作模式定论**（强制，凌驾于本文件一切任务之上）：禁 compat shim/胶水/tricky/过程式硬编码/双通道；质量优先；原则优先于行为维持；可推翻项目自身设计缺陷。
3. **当前主线块**（`🔴 当前主线`）：
   - 用户裁定的主线目标
   - 范围分解（子任务序列）
   - 完成状态（已完成哪些）
   - 下一步（开工点）
4. **独立并行任务**（低优先级，不混主线）。

## 更新纪律

- 每完成一个任务：把对应条目**从本文件移除**（不是标完成——已完成即不"最紧要"）。
- 每进入新主线：重写顶部锚点 + 当前主线块。
- 不冻结测试数字（以实跑为准）。
- 本文件只放当前最紧要项；历史进入 git 或 PENDING_TASKS。

## 完成标准

读者读完本文件应能回答三个问题：
1. 现在在做什么？
2. 下一步是什么？
3. 有哪些硬约束（工作模式定论）？
