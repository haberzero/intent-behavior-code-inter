# 任务控制文档机制 — 体系总览

> 一套用**文档体系管理长期工程任务**的机制。回答：用什么文档、各自负责什么、怎么编写、怎么更新、生命周期如何。
> 与 goal 机制（见 `07_goal_mechanism.md`）配合：goal 提供"目标生命周期"，任务控制文档提供"目标的可观察记录载体"。

## 一、文档分类

| 文档 | 类型 | 职责 | 生命周期 |
|------|------|------|---------|
| `NEXT_STEPS.md` | 当前最紧要项 | 记录当前周期最紧要、可立即开工的下一步 | 常驻，随主线推进持续更新 |
| `PENDING_TASKS.md` | 阻塞/搁置规划 | 记录暂时搁置但经过验证仍有有效性的规划 | 常驻，随阻塞解除更新 |
| `WORKLOG.md` | 工作日志 | 记录所有自主决策、质询、方案取舍、变化前后 | 常驻，持续追加 |
| `<重大设计决策>.md` | 决策记录 | 记录重大方向/架构决策的完整依据 | 常驻，决策生命周期内有效 |
| `_<task>.md` | 临时任务文档 | 追踪单个复杂任务的多修改单元 | **临时**，完成后删除 |
| `_HANDOFF.md` | 交接文档 | 让下一 session 完整接续 | **临时**，交接完成后删除 |

## 二、写作原则（对所有任务控制文档通用）

1. **单点真理**：同一事实只在一处维护。任务控制文档之间、与代码/技术文档之间不得复制同一事实的两份。
2. **只放指针与硬规则**：不复制其它文档内容；需要读者查事实时，指向权威源。
3. **以实跑为准，不冻结数字**：测试基线、计数以实际运行为准，不写死。
4. **"只记录，不断决"**：能自主决定的记录决定并推进；只有确实无法决定的才标记为"待决"。
5. **变化前后**：任何实现/测试/文档改动，记录"变化前后"供追溯。
6. **不写项目专属 token 进通用机制**：机制层描述用泛化表述。

## 三、文档间协作图

```
NEXT_STEPS（当前最紧要）── 主线推进 → WORKLOG（决策日志）
      │                                  │
      └── 阻塞/搁置 → PENDING_TASKS      │
      └── 重大决策 → <决策记录>.md       │
      └── 复杂任务 → _<task>.md（临时）   │
      └── 交接 → _HANDOFF.md（临时）──────┘
```

- **NEXT_STEPS**：当前在做什么、下一步是什么。主线每完成一项就更新。
- **PENDING_TASKS**：被阻塞/搁置但仍有价值的规划。阻塞解除后回 NEXT_STEPS。
- **WORKLOG**：所有决策的沉淀。任何自主决定都写这里（或各任务文档的决策记录段落）。
- **决策记录**：重大方向（架构、接口、破坏性变更）的完整决策依据，先于实现写出。
- **临时任务文档**：单个复杂任务的工作簿，完成后删除。
- **交接文档**：session 边界的状态快照。

## 四、文档治理纪律（关键）

- **设计阶段**：设计/决策先写**任务控制文档**（项目级任务控制目录或本机制），**不直接写进技术手册**。待实现落地后，按治理纪律择机收敛写入技术手册。
- **人类手册 vs 任务控制文档**：人类手册（`docs/`）只面向人类，**禁止智能体元信息**（工作流/过程/skill 引用/工具配置）；此类信息只存在于 `AGENTS.md` 与 skill 工作流层。
- **临时文档**：`_` 前缀，完成/交接后经确认**必须删除**，禁止长期留存。
- **删除纪律**：已完成条目从 NEXT_STEPS 移除；临时文档删除前确认状态已由 git 承载。
